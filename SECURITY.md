# Security

This repository contains instructions and documentation rather than a production service. Security risks can still arise when a rule encourages unsafe changes, hides an error, or causes an agent to make an unsupported claim.

## Reporting a concern

Do not publish sensitive exploit details in a public issue. Use a GitHub security advisory when the repository has that feature enabled. If a private reporting path is not available, open a minimal issue without sensitive details and request a private channel from the maintainers.

Include the affected file, the behavior that creates risk, the smallest reproducible example, and the evidence used to verify the concern. Do not include credentials, private source code, or personal data.

## Scope

Report issues involving:

- instructions that can cause unsafe or unauthorized repository changes
- guidance that suppresses errors or bypasses validation
- documentation that makes a material claim without a traceable source
- workflows that execute untrusted content with unnecessary permissions
